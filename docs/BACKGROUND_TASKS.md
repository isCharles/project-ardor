# 后台任务与结果提醒

## 使用

左侧“更多”中的“后台任务”汇总简历分析、面经整理、知识库向量化、学习生成与评分、面试回放和模拟面试评价。排队和运行状态不会阻止用户切换模块；30–120 秒仅是参考范围，不是精确预计完成时间。

完成或失败的结果带有未读提示。用户查看具体结果或点击“标记已读”后，只清除该结果的提醒；进入某个模块不会清除整组通知。服务端保存已读状态，刷新、重新登录或后端重启后仍可恢复。失败可重试，原始输入留在原业务任务中，不复制到通知系统。完成后的重试结果是新的提醒；向量化自动补齐的同一次失败不会不断制造新提醒。

## 工程边界

V34 增加 `background_task_reads`、`knowledge_index_tasks` 及只读视图 `background_task_catalog`。视图只投影状态、标题和结果地址，不暴露简历正文、面经转录、学习回答或 API Key。历史终态任务在升级时标为已读，避免把旧记录变成大量新提醒。旧执行队列仍是唯一执行真相，没有引入外部消息队列。

V35 按结果版本保存各次已读记录，迟到的旧已读请求不会覆盖新结果的已读状态。测试环境把通用 AI 任务的失联阈值临时缩短为 10 秒、心跳改为 1 秒，并限制数据库连接池为两个连接，以验证重启恢复与并发检索；正常部署默认仍为 5 分钟和 30 秒，不修改本机连接池配置。

- 所有列表、摘要、详情、已读和重试请求都从认证上下文取得用户 ID。
- 已读操作携带具体结果的 `completionToken`，旧结果不能顺手清掉新的结果；重复标记同一结果可安全重放。
- 侧栏以服务端未读摘要显示红点；活跃任务期间约 5 秒刷新，空闲约 30 秒，网络异常退避，隐藏页面暂停。
- 任务页支持分批加载历史、失败提示与重试。错误不输出供应商 HTTP Headers 或原始提交。
- 简历、面经和 AI 评估的重试复用已有业务服务；向量化重试重新调度当前用户的待补齐片段。

向量化新增逐文档的持久状态。上传事务提交后由有限异步执行器加速处理；执行器繁忙时，原有片段与任务仍保存在库中，定期补齐继续处理。每次执行带租约，避免并发重复领取；30 秒心跳，5 分钟无心跳按剩余片段恢复为完成或中断。任务完成状态只在向量提交成功之后发布，失败不删除知识文档，也不影响关键词检索。

这里不表示模型调用可以取消。任务中断与停止供应商端生成是不同能力。

## 接口

- `GET /api/background-tasks?offset=0&limit=30`；可按 `kind`、`resourceId` 筛选。
- `GET /api/background-tasks/summary`。
- `GET /api/background-tasks/{kind}/{id}`。
- `POST /api/background-tasks/{kind}/{id}/read`，正文 `{ "completionToken": "..." }`。
- `POST /api/background-tasks/{kind}/{id}/retry`，同样要求结果 token，仅失败状态可重试。

## 验收

隔离数据库与假模型验证跨账号详情/已读/重试拒绝、已读幂等、旧 token 拒绝、重新登录持久性、向量化缺失配置及恢复、原提交保留。升级测试验证历史结果不会成为新通知；后端重启后的浏览器验证任务入口、单条已读和未关联提醒保留。新增测试只允许对一次性验收数据库运行。
