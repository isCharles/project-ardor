# Ardor 权限模式

模式决定交互式 Agent 的工具何时需要确认，不代替用户意图、资源归属、参数校验、
状态转换、取消栅栏、额度或幂等检查。模型结合可信对话理解任务，后端按已登记的
工具能力处理授权，不匹配用户原话中的动作词。外部资料不构成用户授权。

| 模式 | 自动执行 | 需要确认 |
| --- | --- | --- |
| 每次询问 ASK | 查询 | 所有写入 |
| 自动判断 AUTO | 普通单条创建、修改 | 重复日程、定时自动化、结束/取消模拟面试、覆盖投递数量/节奏；本轮第四次及以后的自动写入尝试 |
| 完全权限 FULL | 已登记的创建、修改、执行能力 | 删除及只生成建议卡的操作 |
| 自定义 CUSTOM | 原全局 0–3 等级与模块覆盖指定的范围 | 超出原授权范围的写入 |

删除工具仍只提出带真实所有者目标的界面提案；任何模式都不能自动删除。学习创建
等建议卡适配器保持原合同，模式不把建议改成已执行。已授权定时任务仍使用其原有
持久化任务合同，本次不改写已存在的自动化授权。

AUTO 的分类依据 `ToolCatalog` 的能力、模块和明确高影响操作；未知工具不免确认。
新增工具必须如实登记能力，具有外部执行或范围传播影响的操作不能冒充普通增改。
自动写入尝试按单次运行计数，确认、取消和执行记录复用已有机制。

## 存储与兼容

V65 只新增 `agent_approval_preferences`，不改写 `agent_permission_grants`。
无模式记录时按 CUSTOM 执行，因此升级不会放宽任何已有模块覆盖。
切换预设保留原自定义配置；切回 CUSTOM 恢复原配置。

`PUT /api/agent/permissions/mode` 接收 ASK/AUTO/FULL/CUSTOM；认证上下文确定账户，
非法或缺失模式返回 400。GET 保留原 `globalLevel`、`modules` 并增加 `mode`。
预设对旧客户端显示保守数字投影：ASK=0、AUTO=2、FULL=3，模块均跟随预设；AUTO
的高影响例外仍会询问，旧数字 UI 无法完整表达该区别。

原全局/模块 PUT 和模块 DELETE 均保留，修改时进入 CUSTOM。操作确认卡中的
“以后允许此模块”会说明该切换，并刷新聊天中的模式显示。设置、聊天和确认卡
共享账户配置，没有把权限只存进浏览器缓存。

## 升级、回退与验证

升级验证覆盖真实 PostgreSQL 的 V64→V65、有全局权限和模块覆盖的两账户、切换后
原配置保持、旧接口写入恢复 CUSTOM；另有 HTTP 认证/非法值/隔离验收和浏览器
保存、重载、失败回滚及窄屏测试。真实模型的语义质量不由这些合成测试证明。

代码回退时保留新增表，不改写已执行迁移。**旧后端不理解 ASK/AUTO 预设，不能将
直接启动旧镜像视作等价的权限回退。** 若用户已经选择预设，回退前先检查：

```sql
SELECT count(*) FROM agent_approval_preferences WHERE mode IN ('ASK', 'AUTO');
```

非零时停止直接回退：旧全局/模块值可能比当前预设更宽，需要先保存原配置、按账户
核对并收敛旧权限，或保留新后端仅回退界面。不得自动删除模式记录、清空模块覆盖
或恢复整库来规避问题。首轮部署验证期间没有模式选择时，旧镜像仍可按原授权回退。
