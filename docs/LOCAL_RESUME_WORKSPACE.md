# LaTeX 简历工作区：执行边界与交付阶段

状态：设计，尚未实现；不表示桌面客户端已有本地文件权限。

## 产品合同

用户可以在 Ardor 对话中要求修改简历，在编辑区查看源文件与差异，编译后预览 PDF。
自动保存编辑稿和可恢复的修订；只有用户确认可以投递时才冻结正式版本。
保存、生成 PDF、正式定稿、实际投递是四种不同状态，不互相推断。

参考现有简历工作区的组织规则：`source/` 为编辑源，`build/` 为预览与诊断，
`versions/` 为不可覆盖的正式快照，`res/` 为对外 PDF。参考材料不自动写进简历，
修改不得编造经历或指标。现有工作区导入前先读取目录与规则，不创建替代结构或覆盖原件。

## 两种存储位置，同一业务流程

第一种是 Ardor 管理的工作区：用户上传模板与资料，在服务端隔离环境编译；浏览器和桌面均可用，
不需要访问用户磁盘。第二种是用户选定的本机目录：需要本机执行器在线并完成配对与目录授权。
桌面端可承载该执行器；以后浏览器也可以连接明确配对的执行器，不能仅凭网页登录就访问磁盘。
本机离线时显示离线并保留草稿，不声称本地文件已更新。

业务层记录工作区、文档修订、编译任务和正式产物；执行器负责限定目录内的文件和编译操作。
聊天继续使用 Ardor 当前统一执行入口，不为本地工作区再创建隐藏的第二套会话与权限规则。
本机路径只在本机配置中保存；远端使用不透明 workspace ID，模型提供的路径不构成目录授权。

## 最小执行合同

- 读取：仅已授权目录内的相对路径；拒绝路径穿越、符号链接/重解析点逃逸和未授权文件。
- 修改：基于源文件哈希或修订号提交差异，原子写入；版本不符则返回冲突，不能覆盖用户并行修改。
- 编译：固定工具与参数、独立临时目录、时长/内存/输出大小限制；默认禁用 shell escape 和出站网络。
  TeX 仍可读取文件，禁用 shell escape 不能替代文件系统隔离。编译环境只可见必要模板、字体与输入。
- 产物：关联精确源码修订、编译器版本、诊断与 PDF 哈希。只有对应修订编译成功才能显示成功预览。
- 存档：正式版本不可覆盖，保存 PDF 和可复现源码清单；导出替换已有文件前需明确确认。
- 取消/重试：编译任务有稳定身份和状态，取消后旧任务不能覆盖新预览；重复请求不重复冻结正式版本。
- 归属：服务端工作区按当前用户授权；本机执行器复核配对、任务身份和目录许可，不信任模型自述。

业务的“完全权限”不等于整台计算机权限。新目录、越界操作、删除或覆盖正式版本不能由模型、
简历模板或聊天中的机械确认口令自行授权。文件名、编译日志与上传内容都作为不可信数据处理。

## SDK 选择

公开 SDK 可以减少执行编排工作，但不是本机权限边界的替代品。
[Codex SDK](https://developers.openai.com/codex/sdk) 可从程序启动和恢复本地 Codex 线程，
适合作为可选的工作区代理适配器；若采用它，需要清楚区分 Ardor 会话与被委派任务，
统一呈现审批、取消和 trace，不暗中替换用户所选模型。
[Agents SDK 的 sandbox 能力](https://developers.openai.com/api/docs/guides/agents/sandboxes)
提供文件、Shell 与隔离环境的编排入口；是否支持本机 Windows、所需安装和权限仍须实际验收。

首版建议使用能力受限的工作区工具与固定编译执行器，复用当前 Ardor Agent。
只有通用多文件编辑确实需要独立 harness 时再引入适配器；不为简历功能重写整套 Agent，
也不提前承诺第三方 SDK 能无缝复用所有现有模型和认证方式。

## 阶段与验收

1. 服务端托管工作区：合成模板的对话修改、差异、隔离编译、预览、修订恢复和正式存档；
   覆盖双用户访问、恶意 TeX、编译失败、并行修订和重复定稿，不接触真实目录。
2. 本机连接：桌面目录选择与配对、受限执行器、离线恢复和版本冲突；用临时合成目录测试
   路径/重解析点逃逸、编译沙箱、撤销目录许可、重启与取消。未验证前不能连接个人简历目录。
3. 用户指定真实目录后只读预检和备份，确认模板/规则兼容后开展一次可回退的编辑及 PDF 人工验收。
   原生能力或协议变更必须单独发布桌面版本，不能把前后端 Docker 部署当成桌面已升级。
