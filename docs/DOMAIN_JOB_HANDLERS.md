# 领域任务执行与重试边界

本批属于整体重构 D 阶段的一部分，不代表所有跨域依赖或 E/F 验收完成。保持模块化单体、原任务表、任务类型、API、额度和结果链接；不新增消息总线或通用实体表。

## 所有权

- `AiJobStore` 仍拥有持久化任务的状态、领取、请求摘要和重试身份。执行身份来自已领取的持久化任务，不能用 payload 内的用户或 requestId 覆盖。
- `AiJobService` 注册 `AiJobHandler`，只负责选择和调度。学习生成、学习评估、单题重答、模拟面试评估由各自领域 Handler 调用现有业务 Service；不导入其他领域 Repository 或 Web DTO。
- 领域应用命令与 HTTP DTO 分离，控制器做显式映射。旧任务 payload 的字段、顺序及空值投影保持兼容，兼容测试比较实际序列化结果；不能靠重命名类型破坏历史幂等摘要。
- 学习评估新提交仍检查当前尝试次数及答案数量。相同请求重试允许业务尝试已前进，但仍校验资源所有者，并由 Store 对类型、目标和 payload 摘要做严格比对。
- 历史 `INTERVIEW_EVALUATE` 类型仍表示模拟面试，不迁移成真实面试轮次。手动入口和后台 Handler 共用业务真相源。

## 后台统一重试

`BackgroundTaskService` 先按登录用户读取任务，确认失败状态与完成版本 token，再交给显式注册的 `BackgroundRetryHandler`。各领域保留原来的业务重试入口和扣额规则，知识索引仍先恢复任务再派发。

注册重复类型或空类型立即失败。未知任务类型明确拒绝，不再默认交给通用 AI Job Store。并发状态变化仍由原 Store/领域服务在写入时检查；重试入口不是绕过业务状态机的第二套写逻辑。

新任务类型需要自己的应用命令、领域 Handler、明确的持久化任务类型与结果链接，以及必要的目录/额度合同；不需要往调度与统一重试方法继续追加中央分支。这不是任意插件协议，也不允许模型注册执行器。

## 验证与回退

- `AiJobServiceTests`：重复/缺失注册失败、持久化运行身份、已完成尝试重试不被错误拒绝。
- `BackgroundTaskServiceTests`：先归属/状态/完成版本检查再执行、未知类型拒绝、各领域业务入口与知识索引顺序不变。
- `DomainJobBoundaryTests`：本批调度和执行 Handler 不回到跨域 Repository/Web DTO；两个中央调度方法不恢复类型 switch 或默认领域回退。此检查只约束列出的边界，不声称整个仓库已解耦。
- 完整 Golden Path 继续覆盖真实异步创建/评估/重答、跨用户、失败重试、确认纪要与流式运行；本地隔离实例须实际启动以验证 Spring 注册，不能只靠 mock。

没有 schema 迁移。需要回退时回退这批应用代码即可，历史任务 payload、业务资源与结果链接不变。任务 payload 版本、客户端能力协商、全域依赖清理与真实扩展验收仍需后续实现和证据，不能由这些注册测试代替。
