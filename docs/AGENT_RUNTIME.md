# Agent 运行与功能标签

## 计时口径与一次慢响应复核

2026-10-14 的一次 DeepSeek / Max 执行记录总耗时为 455861ms，已记录工具耗时合计约 41ms。线程采样显示 LangChain4j 的 SSE 解析器停在 JDK HTTP 响应流的 `readLine()`，并非业务工具执行线程的锁等待。仅凭这个采样不能判断远端是在推理、连接停滞，还是未提供可显示的输出。

旧代码把 `firstPartialMs` 算成“首个正文输出至完成”的时间，名称与算法不一致。本次旧记录的 951ms 因而不能证明 0.951 秒内已产生正文；按总耗时推算，首个正文约在 454.9 秒后出现。修正后的算法使用 `firstPartialAt - startedAt`，无正文时记录 -1；回归测试固定首个输出时间，不依赖真实模型。总耗时仍包含模型、等待和工具，不应标成纯思考时间。

工具提案与异步任务须区分：`create_learning_plan` 只提供待确认建议，实际讲解和练习生成发生在用户确认后的后台任务中；工具的毫秒计时并非完整学习生成耗时。

逐次授权的等待与业务执行分别测量：`approvalWaitMs` 从准备请求到批准/拒绝，`businessMs` 只统计真正进入业务执行器的部分；`elapsedMs` 仍保留工具全流程耗时，供整轮归因使用。用户拒绝、权限过期或运行取消后未执行的工具显示 `NOT_EXECUTED`，业务执行为 0，不标成已成功读取或写入。页面优先显示业务耗时，有授权等待时另列一行；历史 trace 和恢复快照保存相同口径。旧记录没有细分字段时继续显示原总耗时，不倒推无法知道的数据。

## 公开输出与断流恢复

### 有限期限与停止边界

`app.agent.stream.silence-timeout` 默认 90 秒，早于默认 120 秒的 HTTP 读取期限，按实际模型正文、公开思考或工具参数片段计时，不按 Worker 心跳续期。30 秒无新数据时给流式页面发等待提示；无输出不推断为“正在思考”或“已经断网”。`app.agent.stream.total-timeout` 默认 10 分钟，限制整轮运行，包含工具和用户授权等待；静默计时则在工具/授权阶段暂停，由各自的执行及授权边界管理。配置必须为正数。若连接或读取层更早返回超时，则标记不可自动重试的 `AGENT_UPSTREAM_TIMEOUT`，不把它误当成普通短暂连接波动。

超时分别标记 `AGENT_UPSTREAM_SILENT` 或 `AGENT_RUN_DEADLINE`，用户停止标记 `AGENT_RUN_CANCELLED`，均不自动重试。新停止接口先按用户核验请求归属；停止会关闭授权、拦截迟到业务调用和最终回复保存。HTTP 包装器在响应头到达后立即注册原始 SSE 响应体的关闭动作，不必等待首个 token；也会请求取消 SDK 当前流句柄。尚未收到响应头时仍受连接/请求超时约束，迟到响应体会立即关闭。不论本地关闭是否成功，都不能承诺供应商的远端计算或计费已经终止。

已进入业务 Service 的操作不能假装撤销：同一用户的执行锁会保留到该调用真正退出，后续工具不再启动。持久化队列遇到失败或停止会保留后续消息等待用户检查，不会借停止自动重放。SSE 不再用固定五分钟连接期限截断仍在输出的运行；后台运行期限负责终结，页面断线仍可通过请求状态恢复。

供应商通过 `reasoning_content` 等协议实际返回的公开思考输出，单独以 `thinking` 事件传输；不从耗时或正文补造思考。正文仍使用 `delta`。已完成回复的公开思考和首个正文延迟保存在原有消息 trace 中，历史记录可折叠查看。公开思考与恢复用正文缓冲各限制为 32000 字符，避免无界内存增长。

`GET /api/agent/runs/{requestId}/progress` 先验证持久化任务归属，再读取同一用户的实时状态。恢复轮询可以取得公开思考、正文片段及等待状态；超过 30 秒没有上游新数据时显示等待，不把 Worker 心跳当作模型在思考。V37 为原任务新增有界进度快照：正文、公开思考各 32000 字符，工具步骤最多 32 项；每秒检查脏数据，终态立即尝试写入。单调版本阻止较早的后台快照覆盖终态。写入失败不会重放业务操作，运行期间会再尝试；崩溃前最后一次成功检查点之后的数据可能丢失。

内存缓冲保留两小时；服务重启或缓冲失效后，按 `id + user_id` 从数据库恢复只读快照，以持久化任务终态为准。失败或中断的正文标记为未完成片段，可展开查看；不当作完整回复，不恢复批准或自动执行工具。检查点不会写入工具参数、凭据或权限决定。已失去服务进程且两分钟没有心跳的请求标记为中断；当前进程仍持有的真实运行不会仅因检查心跳被错误中断。任务状态和进度记录均随所属会话删除。

## 当前深度参数映射

`ModelReasoningPolicy` 以已配置的兼容协议与模型名称决定映射：DeepSeek 的 Low / High / Max 分别为 low / high / max，并启用 thinking；已识别的 OpenAI 模型映射为 low / medium / high；已识别的 Anthropic 模型按版本采用 adaptive effort 或固定预算。Auto 不强行覆盖 effort；未知模型只收到相应的任务深度提示。此表是 Ardor 当前实现，不保证任意中转站都支持相同参数；需要由实际调用验证。

## 删除确认与普通工具执行

按最新产品规则，读取、新增、修改不再逐次弹出权限卡。工具仍绑定当前认证用户并复用业务 Service，校验资源归属、用户意图和输入；运行已结束或已停止时，执行器不再启动业务调用。`ApprovedAgentTools` 保留这个执行围栏，不代表自动重试或重放许可。普通工具的授权等待计时为零，不把执行器检查耗时展示成用户等待。

删除工具只能准备包含真实目标的确认提案，不执行最终删除。适配器显式列入提案目录；未登记的 `delete_` 工具不能绕过围栏。确认卡固定在输入框正上方，显示对象名称、关联影响及不可恢复性。保留不会调用删除接口，确认后才调用受鉴权的业务删除 API。处理中禁用重复提交，失败保留错误与重试入口；等待中的卡片不夹在聊天记录中，结果仍可在记录中查看。手机端限制确认区高度并独立滚动，不覆盖输入框。

学习计划的生成建议卡仍是业务流程中的“生成／暂不安排”选择，不是普通工具权限卡。旧通用授权接口保留兼容读取及已有决定校验，新执行器不再创建普通工具授权请求；旧界面需刷新。删除提案可从已保存的 trace 恢复，但恢复不会发起删除，不能通过聊天口令或外部内容代替点击。同步聊天同样只返回删除提案，没有直接删除通道。

普通修改工具复用当前用户业务授权与运行停止围栏，不逐次弹权限。卡片与面经修改沿用既有完整更新契约，调用前须读取原数据并保留未要求更改的值。学习改期使用单独受鉴权接口和业务行锁；若用户在模型评分期间改期，低分复习保留用户的新时间，不被稍后评分覆盖。已完成计划不通过改期伪造新的未完成练习；需要复习时另建计划。登录、密钥、管理员配置不因业务工具覆盖而开放给模型。

重复规则修改保留规则和实例 UUID，只同步尚未完成、未被单独修改的未来实例；返回更新/保留数量，不删除再造。当前不支持修改频率、日期范围或时区，不能擅自取消重建。规则更新、取消、后台扩展使用同一规则行锁；手动日程更新与批量同步均锁定实例，防止旧状态覆盖用户修改。日历主创建入口直接进入带所选日期与功能标签的未发送 Ardor 草稿，手动输入保留为次级入口。

学习计划的手动删除入口和 `delete_learning_plan` Agent 工具均复用已有 `/api/learning-plans/{id}` 删除接口。Agent 先通过归属检查取得真实计划标题，只返回待确认提案，不删除数据；用户点击后由认证接口删除。已有外键级联删除关联日历任务；创建请求墓碑避免历史生成按钮复活已删除计划。练习评估提交时再次按用户及计划 ID 加锁加载，已删除计划不能重新写回。后台任务记录不被清空，已失效的评估会保留失败结果供用户核验。

## 编辑器与已发送消息

每轮执行过程只保留一个展示入口：位于该轮最终回复之前的轻量折叠摘要，默认关闭。供应商公开思考输出与工具步骤收在同一个摘要里，不另做突出卡片。最终回复从服务端载入后清除临时思考、步骤、重试和进度副本，避免实时状态与历史 trace 同时展示；停止按钮不藏在折叠内容里。刷新后仍从已保存的消息 trace 恢复，不能通过去重而丢弃历史执行记录。

当前设备将已发送消息单独存入按账户及会话隔离的 outbox，不再占用下一条消息草稿。断流或状态暂时无法核实时，已发送内容保留在聊天记录，不自动重新发送，也不覆盖用户正在输入的内容。持久化执行恢复时可从任务正文重建用户气泡；完成后只清除对应 outbox，而不清除新草稿。

未发送正文、资料引用与服务标签同样按账户和会话保存在当前设备的 sessionStorage。刷新、切页及切换账户后，只恢复对应账户的草稿；资料引用的移除也同步保存。没有归属信息的历史旧草稿槽位不自动导入另一个账户。资料引用仍只是选择，真正发送时由后端核验资源归属。

执行期间输入框与深度选项可编辑；深度改变只用于下一条请求，不能修改正在执行的供应商参数。outbox 是当前浏览器会话内恢复辅助，不等于服务端消息队列。

## 持久化消息队列

新增迁移 V36 仅添加 `agent_message_queue`，不改写既有迁移或用户消息。`POST /api/agent/queue` 接收已有会话的消息、引用、深度和固定请求 ID；先校验当前用户会话、引用和模型配置，按当前用户串行入队，同一 ID 的不同内容会被拒绝。请求重试复用 ID；计费在受鉴权入口按同一 ID 幂等，Worker 不重复消费接口额度。每用户最多 20 条待处理消息。

Worker 通过带用户限定与 `SKIP LOCKED` 的原子领取保持先后顺序，且不与同一用户的已运行请求并发执行。执行时重新核验资源、调用同一 Agent Service 和执行围栏，删除仍只生成待确认提案。实时正文从受鉴权进度接口恢复，最终回复仍保存到原会话。

消息绑定前驱：前驱成功才自动继续；失败或中断会停住后续消息，用户检查结果后可显式继续。只能移除尚未开始的消息，移除会调整后续依赖。未知派发状态不会自动重放；仅当确认没有持久化 run 且服务明确返回 `AGENT_BUSY` 时，才复用原 ID 留在队列等空闲。服务崩溃后没有 run 的旧派发标为待确认，不靠猜测重新执行。

用户可对指定排队消息选择“现在处理”或“打断并立即处理”。`POST /api/agent/queue/{id}/steer` 在同一事务中锁定并验证排队消息，防止另一个窗口先移除目标却仍停止旧运行；指定当前 run 时再次校验同一用户、同一会话，再停止旧运行并将所选消息置于优先位置。停止不是回滚；已进入业务 Service 的操作仍可能完成，执行锁继续保护串行性。只解除所选消息的前驱，不重放旧请求、不一并放行其他暂停消息。排队 payload 与 UUID 不改变；用事务级 advisory lock 分配比当前最小序号更低的唯一优先位置，最后一次选择优先，无 schema 变更。列表按提交时间呈现，不按处理优先级倒置聊天记录。

普通写入不弹逐工具确认，但服务端按本轮用户原始请求提供保守的功能范围，不能由检索结果授予新的写入能力；未识别的表达会要求自然澄清，不是完整自然语言意图证明。长期记忆必须取自用户明确提供的原话。同步旧入口没有持久化执行 ID，仅允许读取和确认提案，写入使用队列/流式持久化运行。批量删除提案固定携带当时的 UUID 快照，认证接口先验证全部归属后才删除，不能扩展到后来新增的内容。旧版无快照批量提案过期；本设备按账户、会话和提案消息保存保留/完成状态，刷新不重新弹出，不宣称跨设备同步。

排队消息以普通用户气泡显示，状态与操作在下方；先前运行的结束/失败记录在前，新消息在后。队列发现新运行开始时唤醒当前会话的运行状态恢复。恢复轮询只复用属于当前请求的 outbox，并按稳定消息 ID 去重；不得把旧请求缓存正文反复追加到新请求。

队列正文和状态保存在服务端，刷新或切页不会丢失；未确认接收前的提交 ID 暂存在按账户和会话隔离的浏览器槽位。页面展示排队、执行、失败及手动继续/移除入口。Golden Path 包含真实数据库的顺序、幂等、用户隔离与失败暂停/继续断言；CI 还分别启动全新 V36 库和带消息哨兵的 V35 升级库验证迁移。测试结果须以相应运行成功为准，本机 Docker 不可用时不得宣称正式库部署已经验证。

## 功能标签

`GET /api/agent/features` 返回服务端维护的目录。输入框开头的 `@` / `$` 只用于呼出选择器，选中后显示可更换和移除的服务标签。创建入口使用固定的功能 key 与示例正文进入空白对话，不自动发送，也不创建业务资源或侧栏会话。

标签作为 `SERVICE` 类型的 `contextReferences` 发送，ID 由服务端校验，名称与意图提示也由服务端生成；用户不能把任意字符串伪装成服务，更不能通过标签取得工具授权。引用继续使用既有 JSON 字段保存，无需改写已执行的 migration。服务选择按账户和草稿会话保存在当前设备的 sessionStorage；历史标签显示为对应模块链接。资料引用仍由业务 Service 核验用户归属。
