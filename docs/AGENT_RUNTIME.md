# Agent 运行与功能标签

## 计时口径与一次慢响应复核

2026-10-14 的一次 DeepSeek / Max 执行记录总耗时为 455861ms，已记录工具耗时合计约 41ms。线程采样显示 LangChain4j 的 SSE 解析器停在 JDK HTTP 响应流的 `readLine()`，并非业务工具执行线程的锁等待。仅凭这个采样不能判断远端是在推理、连接停滞，还是未提供可显示的输出。

旧代码把 `firstPartialMs` 算成“首个正文输出至完成”的时间，名称与算法不一致。本次旧记录的 951ms 因而不能证明 0.951 秒内已产生正文；按总耗时推算，首个正文约在 454.9 秒后出现。修正后的算法使用 `firstPartialAt - startedAt`，无正文时记录 -1；回归测试固定首个输出时间，不依赖真实模型。总耗时仍包含模型、等待和工具，不应标成纯思考时间。

工具提案与异步任务须区分：`create_learning_plan` 只提供待确认建议，实际讲解和练习生成发生在用户确认后的后台任务中；工具的毫秒计时并非完整学习生成耗时。

## 公开输出与断流恢复

供应商通过 `reasoning_content` 等协议实际返回的公开思考输出，单独以 `thinking` 事件传输；不从耗时或正文补造思考。正文仍使用 `delta`。已完成回复的公开思考和首个正文延迟保存在原有消息 trace 中，历史记录可折叠查看。公开思考与恢复用正文缓冲各限制为 32000 字符，避免无界内存增长。

`GET /api/agent/runs/{requestId}/progress` 先验证持久化任务归属，再读取同一用户的实时状态。恢复轮询可以取得公开思考、正文片段及等待状态；超过 30 秒没有上游新数据时显示等待，不把 Worker 心跳当作模型在思考。实时状态只保留两小时且不跨服务重启，不能替代持久化任务状态；完成或失败后迟到回调不能改变终态。该实时缓冲不是超时取消机制，有限上游截止时间与取消仍需独立实现及验证。

## 当前深度参数映射

`ModelReasoningPolicy` 以已配置的兼容协议与模型名称决定映射：DeepSeek 的 Low / High / Max 分别为 low / high / max，并启用 thinking；已识别的 OpenAI 模型映射为 low / medium / high；已识别的 Anthropic 模型按版本采用 adaptive effort 或固定预算。Auto 不强行覆盖 effort；未知模型只收到相应的任务深度提示。此表是 Ardor 当前实现，不保证任意中转站都支持相同参数；需要由实际调用验证。

## 编辑器与已发送消息

当前设备将已发送消息单独存入按账户及会话隔离的 outbox，不再占用下一条消息草稿。断流或状态暂时无法核实时，已发送内容保留在聊天记录，不自动重新发送，也不覆盖用户正在输入的内容。持久化执行恢复时可从任务正文重建用户气泡；完成后只清除对应 outbox，而不清除新草稿。

执行期间输入框与深度选项可编辑；深度改变只用于下一条请求，不能修改正在执行的供应商参数。当前仍只允许一条请求执行，顺序队列尚需补齐。outbox 是当前浏览器会话内恢复辅助，不等于跨设备消息队列。

## 功能标签

`GET /api/agent/features` 返回服务端维护的目录。输入框开头的 `@` / `$` 只用于呼出选择器，选中后显示可更换和移除的服务标签。创建入口使用固定的功能 key 与示例正文进入空白对话，不自动发送，也不创建业务资源或侧栏会话。

标签作为 `SERVICE` 类型的 `contextReferences` 发送，ID 由服务端校验，名称与意图提示也由服务端生成；用户不能把任意字符串伪装成服务，更不能通过标签取得工具授权。引用继续使用既有 JSON 字段保存，无需改写已执行的 migration。服务选择按账户和草稿会话保存在当前设备的 sessionStorage；历史标签显示为对应模块链接。资料引用仍由业务 Service 核验用户归属。
