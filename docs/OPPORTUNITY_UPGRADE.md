# 面试流程升级与历史面经

面经只保存文档内容及所属面试，公司、岗位、时间均由面试流程/轮次维护。

- 不改写已经执行的 V40–V46，避免 Flyway 校验和冲突。
- 新增 Flyway `beforeEachMigrate__preserve_legacy_recap_metadata.sql` 回调：旧列仍存在且流程表已创建时，先把历史公司、岗位和时间迁入同用户的流程/历史轮次，再由原 V43 删除旧列。回调重复运行不会重复建轮次，也不会覆盖已关联流程的用户字段；原值保留在历史轮次说明中。
- 旧记录没有公司时使用明确的 `Imported interview` 占位名称，不猜测真实公司；完全没有旧元数据的孤立文档可由用户重新提交后绑定面试。
- 已经执行 V43 的数据库，旧列信息已经丢失，后续迁移无法凭空还原。需要恢复时仅从经验证的备份取回，再经归属核验绑定；不自动改写真实数据或重建全部数据库。
- V47 校准早期推断记忆的默认置信度，并让已有向量从当前文字重新补齐，不改变显式记忆事实。

验证同时覆盖 SQL 干净迁移、重复回调和真实 Flyway 从带历史面经的 V35 数据库升级。业务接口用缓存命中时绑定未关联文档；已经属于另一场面试的相同内容会明确报错，不静默移动。
