# 助手工具模块与统一执行边界

## 当前实施范围

知识资料的四个工具已从 `CareerAgentTools.BoundCareerTools` 移入助手域的 `KnowledgeAgentToolProvider`：`list_knowledge_documents`、`search_knowledge`、`research_knowledge_from_web`、`delete_knowledge_document`。

模块仍调用资料域 `KnowledgeService` 的应用快照接口，不拥有知识实体、仓储、索引或删除事务。工具名、参数名、scope、HTTP 路径和结果含义保持兼容。本批无 schema 迁移，也不改变用户权限设置。这是进程内适配器拆分，不是插件平台：不加载用户上传代码，不允许模型登记工具，也不新增独立服务。

## 装配与生命周期

Spring 发现 `AgentToolProvider` 组件并交给宿主；已有直接构造入口默认装配知识模块，供旧测试和调用方兼容。每次 `bind` 都创建新的绑定对象，`AgentToolContext` 捕获本轮可信用户及宿主的提案、不可信内容包装回调，不通过模型参数选择用户。

`AgentToolBundle` 只提供不可变的绑定对象列表。普通对话、流式对话及自动化继续经过 `ApprovedAgentTools`，不直接将提供者暴露给模型框架执行。连接测试使用同一发现入口收集 schema，但工具执行器仍为原有 no-op，不产生业务副作用。

重复工具名在执行装配时拒绝，不以发现顺序覆盖已有工具。扩展提供者不能绕过能力目录；新增工具仍须登记现有 `ToolCatalog`，并按需要补齐明确意图、权限与业务服务校验。局部适配器避免中央类继续增加工具方法，不意味着取消中央安全策略。

## 必须保留的执行合同

1. 写入授权继续由**宿主绑定的可信请求**控制，而不是由被拆出的工具对象自行声明。`ToolIntentScope` 的判断对象仍是根绑定对象。
2. 全部模块共用同一轮的重复写入防护、审批、运行 lease、取消、计时、追踪与执行审计。不得按模块另建尝试缓存而允许重复副作用。
3. 资料检索及网页收录结果继续使用 `untrusted_external_content` 包装；材料中的命令不能授权写入。
4. 删除工具先通过用户限定的应用服务读取真实目标，再调用宿主提案回调。查不到目标不得生成确认卡；工具不调用删除业务方法。最终删除仍由用户界面确认后的受鉴权 HTTP 接口执行。
5. 提案留在宿主本轮的待确认列表，保留现有结构化审计与恢复身份，不因对象拆分改成模块私有列表。

## 验证与回退

`ModularAgentToolsTests` 验证实际宿主和模块装配、schema 与执行集合一致、能力目录覆盖、重复名称拒绝、来源包装、可信用户传递、意图拒绝、审计、写入去重、取消以及删除提案。架构守卫禁止模块导入知识仓储/Web DTO/实体，并禁止知识检索/收录工具方法回到中央宿主。

Golden Path 新增真实模型—工具—业务服务回路：合成用户上传资料，假模型检查四个工具 schema 并调用文档列表，回复必须含本用户文档且不包含另一用户文档。它验证真实装配和数据库授权，不代表真实供应商模型质量或付费服务连通性。实际 CI 结果另行记录。

本机 Java 21、干净源码及一次性 PostgreSQL 的完整后端回归：581 项测试，0 失败、0 错误、1 跳过（旧会话运行时探针未显式开启）。报告在忽略目录 `backend/target/knowledge-module-reports`，临时库与网络已清理，未动日常卷。首轮跨用户用例误期望框架抛异常；核对 `DefaultToolExecutor` 的既有错误字符串合同后，改验“返回不存在、无确认卡、未删除”并重新完整通过，不改产品错误行为。

首轮 Golden Path 的新模型调用及归属内容断言已通过，随后用例误调用不存在的文档详情 GET，返回 405。按既有 HTTP 合同改验跨用户 DELETE 返回 404，并再由所有者列表确认文档仍在；不为满足测试新增产品 API。需核对修正后的整套 CI。

本批只改应用代码，无数据转换；可回退本批代码而不回滚数据库。不要据此将 DSH 的 V60/V61 回退为旧二进制兼容，也不要删除历史运行/审计数据。最终 CI 和部署须分别核验。

## 尚未完成

其余领域工具仍在中央宿主；上下文引用解析仍访问 `KnowledgeService`；能力目录、意图与部分跨域编排仍有中央分支。后续按领域提取，不先建立万能工具实体或通用工作流引擎。本批不代表整体架构重构完成。
