# 转录、确认纪要与复盘

## 最新产品方向：最终纪要直接规范化

用户已明确将流程简化为：**提交最终纪要 → 保存纪要 → AI 异步规范化整理 → 渲染结果**。不再要求保存独立的“原始转录”、生成待校正初稿或再次确认纪要；提交最终纪要本身就是发起整理的明确意图。

- 新入口以用户提交的最终纪要作为唯一事实来源，AI 不补造问题、回答、经历或缺失细节。
- 保存的纪要与对应规范化结果应关联同一面试/轮次；后台失败仍保留已提交纪要，并提供清楚的状态与重试入口，不让用户重贴。
- 不再向用户呈现原始转录/初稿/确认快照三个并列层级；历史数据暂时保留，不能为简化新流程而删除旧资料或改写已执行迁移。
- 新页面与 `organize_interview_recap` 工具均调用最终纪要入口；不替用户生成或确认事实初稿。提交后返回已持久化的任务，Worker 直接规范化并保存结构化结果。

### 当前实现与兼容边界

- `POST /api/interview-recaps/final-minutes` 提交内容与真实面试/可选轮次；`GET /final-minutes/{id}` 读取本人保存的完整纪要和状态，列表接口只返回前 100 字预览，最多 20 项。所有归属仍由业务服务校验。
- 新提交使用 V59 的 `final_minutes` 模式及独立指纹，不复用旧转录任务。历史 `raw_content` 列名暂为兼容保留；在新模式中存储的就是用户最终纪要，不另生成“原始转录”和待确认初稿。
- 旧任务默认保持旧模式；旧 API、确认记录和历史报告不删除、不改写。新模式不会出现在旧初稿列表或旧初稿读取接口，避免再次进入确认流程。
- 新任务通知直接链接 `?minutes=任务ID`；完成后页面展示对应结果并可展开保存的纪要。失败后通过既有受鉴权重试接口重新排队，仍使用保存的纪要，不要求重贴。
- 整理提示版本为 `final-minutes-normalization-v1`，按已有分段/精确去重边界处理长纪要；模型规范化不等于事实正确性保证。没有评价依据时要求 UNKNOWN，不要求模型额外编写答案或建议。
- 本批有单元测试、带旧任务的 V58→V59 升级探针及真实浏览器验收；最终 CI、合并和日常部署必须分别核对。下文仅描述旧实现及历史验证。
- 回退边界：旧二进制不识别最终纪要模式。回退前须暂停新提交、等待新模式的排队/运行任务结束；不能让旧 Worker 将未完成的新任务当作转录初稿处理。V59 列与历史数据保留，不通过删列、改模式标志或重放用户提交实现回退。

## 旧实现与历史验证

新提交不再直接生成面经报告。原文保存在原有 `interview_recap_jobs.raw_content`；异步 Worker 按版本化 `skills/interview-minutes/SKILL.md` 分段生成事实纪要，写入 `interview_minutes`。初稿不评价，明确标记噪声、角色和术语不确定处。现有旧面经不修改、不回填确认状态。

聊天入口直接保存服务端绑定的本轮用户消息（可包含整理指令），不让模型复述长转录或把模型摘要冒充原文。转录在上文、附件或其他来源时，应先让用户把完整内容提交到本轮或纪要页；工具不能凭空补写来源。

旧报告提供“校正原始纪要 · 保留这份报告”入口，用原文开启新流程；已经来自确认流程的报告则回到其原始纪要。新输入采用版本化指纹，不复用旧版直接生成的报告绕过校正阶段。

用户在面经页编辑，服务端按所有者与 revision 乐观锁保存。编辑区使用按用户、任务隔离的 sessionStorage 恢复未成功保存的输入；此本地副本不是跨设备同步。服务端已保存的版本可跨设备读取，冲突不会自动覆盖。确认前先保存，确认绑定不可变的纪要快照。用户可以确认尚有不确定内容，不要求补齐事实。

只有受登录鉴权的 `POST /api/interview-recaps/drafts/{id}/confirm` 才提交详细复盘；没有 Agent 确认工具。相同 draft/revision 只生成一份任务。后续编辑递增版本，不改变历史确认快照和复盘。失败保留原文、纪要和快照，用户可重试。

复盘 Worker 只读取快照，不读取原始 ASR；长纪要分段处理，精确重复问题去重。报告记录 `confirmed-minutes-review-v1`。每个模型输出仍需人工判断；分段和人工确认不保证模型评价一定正确。不能据此声称建立了真实模型质量评测体系。

新转录按一次完整工作流消耗 INTERVIEW_RECAP 额度，包含初稿及首次确认后的复盘，不会让仅剩一次额度的用户卡在确认。后续确认新版本、手动复盘重试另计一次；扣额 ID 由服务端绑定版本/尝试，不采信客户端随意复用的 UUID。复盘重试复用原快照，后台不自动反复请求真实模型。运行中断超过20分钟的复盘标记失败，迟到执行不能覆盖新尝试。后台初稿继续使用最多5次的可重试网络恢复。

打开已有确认纪要只是读取，不消耗生成额度；由旧报告新建初稿才计生成额度。初稿失联恢复窗口扩为30分钟，避免长材料多段请求仍在执行时被原10分钟阈值误判中断。

无面试归属的旧报告先由用户选择一场自己拥有的面试，原报告不改挂。旧版已完成但报告已删除且没有初稿的任务不列作待编辑纪要。

数据库升级使用 V49，不修改原迁移。验证包括旧库升级、空库迁移、确认前无报告、双用户隔离、版本冲突、确认幂等、快照不变与失败重试。真实用户材料不进入测试 fixture 或 Git。
