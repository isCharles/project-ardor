# Ardor 体验设计原则

> 本文是 Project Ardor 当前唯一有效的设计方向。它替换此前以 “Ardor Thread”、绝对三色、深色落地页比例和组件母题为核心的旧文档。

## 一句话理念

**设计一次连续发生的职业体验，而不是拼装一组看起来属于同一品牌的页面。**

Ardor 的核心不是“很多 AI 功能”，而是用户说出一件想推进的事，系统理解已有上下文，并把它继续向前推进。公开首页、注册、登录和工作台都应服务这条体验。

## 1. 连续性高于组件感

页面不应让人感到自己从一个 `section` 跳进另一个 `section`。内容可以分幕，但空间、颜色和动作必须连续。

- 滚动不是浏览几个独立模块，而是进入下一个场景。
- 背景变化作用于整个浏览器视口，不关在卡片或局部方框里。
- 场景切换优先使用渗入、覆盖、上浮和尺度变化，避免硬切背景色。
- 快捷入口必须重演对应的空间转换，不能瞬间跳到目标锚点。
- 组件边界只有在帮助理解或操作时才出现，不把每段内容都装进卡片。

当前首页的关键转场是：模块展示结束后，白色基底上的彩色环境光随滚动覆盖整个视口，聊天框随后上浮。`Ask Ardor. Move forward.` 快速滚动到该处时也必须触发同一过程。

## 2. 一个页面，只突出一个动作

用户应在一秒内知道哪里可以操作。

- 首屏唯一主要动作是 `Ask Ardor. Move forward.`。
- 主要动作可以使用明确的实心色、边界、悬停位移和方向图标。
- 其他链接、状态和说明主动降级；没有必要就删除。
- 不在同一视觉层级放置多个同样醒目的按钮。
- 不用“了解更多”“探索系统”这类模糊动作代替真实结果。

首页的主要动作不是“继续看介绍”，而是进入对话体验。

## 3. 文案短、响亮、可行动

视觉冲击来自一句准确的话，不来自解释段落的数量。

- 标题优先控制在一到两行。
- 一句话能说完，就不用眉题、正文和脚注重复三遍。
- 删除装饰性年份、在线状态、协议编号和无行动价值的小字。
- 英文负责形成节奏和态度，中文负责消除歧义。
- 避免无法兑现的万能承诺，例如 “I’ll fix everything”。
- 行动文案必须说明方向，例如 `Ask Ardor. Move forward.`。

对话体验标题使用 `What's next?`，因为它比完整解释产品能力更直接，也把回答空间留给用户。

## 4. 色彩是环境，不是色块

Ardor 不再受绝对三色约束。登录后的用户工作台与管理员工作台统一采用**白色基底 + 大范围、低边界的鲜艳环境光晕染**；深色只用于正文、图标和确有叙事需要的局部对比场景，不作为工作台的大面积背景。色彩按照角色使用：

| 角色 | 作用 |
| --- | --- |
| 黑与暖灰 | 仅用于文字、图标、细线与必要的局部对比 |
| Ardor 橙红 | 标记首要动作、当前焦点和方向性 |
| 酸性绿 | 作为少量技术信号，不铺成大面积广告底色 |
| 粉、蓝、橙、浅绿环境光 | 在进入对话时为整个视口带来情绪变化 |
| 暖白 | 承接环境光，让界面保持开放、轻盈和可阅读 |

规则：

- 渐变优先作为页面级环境光，而不是某个矩形区域的背景。
- 用户端和管理员端共用白色、轻盈、鲜艳晕染的空间基线；两者通过信息架构区分，不通过一黑一白区分。
- 不根据操作系统深色模式自动把工作台翻成炭黑背景；若未来提供深色主题，必须作为独立、完整、可验收的产品能力设计。
- 多色可以存在，但降低饱和度、扩大扩散范围、避免清晰色块边界。
- 大面积高饱和色只在确有叙事必要时使用；CTA 默认采用半透明暖白或浅鼠尾草，而不是荧光绿整块铺底。
- 文字对比必须清楚，但不通过纯黑配荧光底制造持续视觉疲劳。
- 玻璃效果只用于承载输入框或关键浮层，不把所有内容玻璃化。

## 5. 动效必须改变空间关系

动效的职责是告诉用户“正在进入哪里”，不是证明页面会动。

### 应该做

- 根据真实滚动进度改变页面级色彩层透明度、模糊度和尺度。
- 聊天框在背景接管视口后再上浮，形成先环境、后交互的顺序。
- 锚点点击使用程序化平滑滚动，并由同一滚动进度驱动转场。
- 输入框提示可以使用克制的打字机循环，示范可提出的问题。
- Agent 的真实执行过程使用流式事件逐步显示。
- 尊重 `prefers-reduced-motion`，减少位移和缩放，但保留信息状态变化。

### 不应该做

- 点击后瞬移到另一个页面片段。
- 进入新 `section` 时突然更换整块背景。
- 给每张卡片添加无意义的漂浮、闪烁或呼吸。
- 为了显得“流式”而伪造与真实执行无关的步骤。

## 6. 对话是首页与产品的接缝

公开首页最终必须自然收束到一次对话，而不是功能清单或传统注册 CTA。

首页对话框是体验预演：

- 可以输入文字。
- 输入框内循环显示真实任务示例，不在下方堆快捷按钮。
- 点击发送或按 Enter 后进入登录。
- 不声称已经调用真实 Agent。
- 不添加“预览模式”“Enter 发送”等多余说明。

登录后的工作台才执行真实对话、工具调用和数据修改。

## 7. 公开页面与工作台的分工

### 公开首页

- 负责建立期待、展示系统气质并引导第一次对话。
- 可以有强尺度、编辑式构图、Canvas 图形和环境动效。
- 说明文字尽量少，依靠场景和交互表达产品。

### 注册与登录

- 负责快速完成身份转换，不继续讲完整产品故事。
- 一句主张、一句补充、一个表单已经足够。
- 表单必须醒目、清楚、无营销噪声。

### 工作台

- 负责长期使用，优先稳定、熟悉、清晰和信息密度。
- 不强迫工作台复制公开首页的戏剧性。
- 两者通过同一个核心动作连接：向 Ardor 说出下一件要推进的事。

## 8. AI 感来自行为，不来自装饰

Ardor 看起来像 AI 产品，是因为它：

- 能接受自然语言输入；
- 会记住上下文；
- 能调用真实工具；
- 会逐步显示执行过程；
- 能把结果落实为简历、面试、记忆卡和日历变化。

不要用大段 “AI / AGENT / SYSTEM / PROTOCOL” 标签、紫蓝渐变、粒子或科技术语代替这些行为。

Agent 进度必须忠于真实过程：

- SSE 事件到达后逐帧绘制，不能在完成时批量出现。
- 快速工具显示毫秒，不显示误导性的 `0.0 秒`。
- 模型思考与生成耗时单独归入“理解请求与生成回复”。
- 总耗时与分项应能解释彼此，而不是做装饰性计时。

## 9. 排版靠构图，不靠字体噱头

项目继续使用中文友好的系统字体栈。识别度来自：

- 明确的字号跨度；
- 不对称但稳定的构图；
- 紧凑的大标题行高；
- 等宽小字只用于真正的结构信息；
- 足够的留白和少量高对比动作。

不要把“超大黑字”本身当作设计。大字必须和尺度变化、色块关系、对齐方式或交互目标共同形成构图。

## 10. 参考素材的使用边界

`next-gen-infrastructure-protocols-DESIGN.md` 和参考 HTML 只提供以下历史参考：

- 首屏尺度；
- 编辑式网格；
- 模块节奏；
- 尺度与留白的对比方式；
- Canvas 图形的空间组织。

它们不是 Ardor 的产品理念，也不是必须逐字保留的设计规范。不得照搬基础设施文案、协议编号、工业终端风、字母索引、页脚结构或大面积暗色。每个参考元素都必须经过职业 Agent 语义和当前页面节奏的重新判断。

## 11. 已废止的旧原则

以下规则不再适用，不应被后续 Agent 或设计工具恢复：

- “Ardor Thread 是唯一视觉母题”。
- “落地页必须是炭黑，登录后必须暖白”的固定明暗比例。
- “全站只能使用炭黑、暖白、橙红三色”。
- “禁止发光团、渐变或环境光”。
- “所有页面都必须出现轨迹线、节点或竖线”。
- “参考 HTML 是视觉 source of truth，必须保持原有色彩模式”。

职业连续性仍是产品语义，但不再被强制翻译成一条线。它可以通过滚动、背景接管、对话延续、真实数据变化和执行过程来表达。

## 12. 每次改动前的检查

提交设计前逐项确认：

1. 用户第一眼知道唯一主要动作是什么吗？
2. 能否删除一半辅助文字而不损失理解？
3. 这一幕与上一幕是连续进入，还是硬切出来？
4. 渐变作用于环境，还是被关在一个矩形里？
5. 动效是否表达空间或状态变化？
6. 快捷跳转是否保留原本的转场体验？
7. 公开页是否最终收束到对话？
8. 工作台是否保持可用，而不是复制营销页效果？
9. Agent 展示的进度、时间和结果是否真实？
10. 是否正在无意识恢复已经废止的 Claude 设计教条？

如果一项视觉元素无法支持层级、连续性、交互或真实状态，就删掉它。
